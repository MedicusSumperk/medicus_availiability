MEDICUS API - kratky handover pro ElevenLabs testovaciho agenta
=============================================================

Podrobnejsi verzovane dokumenty:

- docs/elevenlabs_agent_behavior_cs.md
  Pravidla chovani agenta, overovani, opakovane hledani terminu a copy-ready
  prompt.
- docs/elevenlabs_tool_config_cs.md
  Nastaveni ElevenLabs toolu, body parametru, dynamic variables a smoke testy.
- docs/elevenlabs_dynamic_variables_compact_v0.json
  Kompaktni copy-ready enum seed pro procedure_list a doctor_list.
- docs/elevenlabs_dynamic_variables_v0.json
  Detailni referencni katalog pro n8n, prompt design a audit.

Pred testem doplnte aktualni BASE_URL z trycloudflare:

BASE_URL: https://DOPLNIT-AKTUALNI-URL.trycloudflare.com

Health check:
GET {BASE_URL}/health

Aktualne jsou pripraveny dva read-only POST tooly a jeden zapisovaci tool
zapnutelny lokalnim configem:

1. doctor_availability
2. patient_lookup
3. appointment_write

Registrace noveho pacienta zatim neni implementovana. Zapis objednavky,
zruseni a presun terminu jsou dostupne pres appointment_write pouze pokud jsou
zapnute lokalni write flags.


TOOL 1: doctor_availability
===========================

Endpoint:
POST {BASE_URL}/doctor-availability

Body parametry:

| name        | type       | required | fixed value | description |
|-------------|------------|----------|-------------|-------------|
| service     | string     | ano      |             | Typ sluzby. Pouzit skin pro kozni vysetreni. Pouzit plasma pouze pokud pacient vyslovne zada plazmu. |
| doctor_name | string     | ne       |             | Jmeno nebo prijmeni lekare tak, jak ho rekl pacient, napr. Bednar nebo Bartonova. Nepouzivat doctor_id. |
| date_from   | string     | ne       |             | Pocatecni datum hledani ve formatu YYYY-MM-DD. Vyplnit jen pokud pacient uvede datum nebo obdobi. |
| date_to     | string     | ne       |             | Koncove datum hledani ve formatu YYYY-MM-DD. Vyplnit jen pokud pacient uvede rozsah. |
| days_ahead  | integer    | ne       |             | Pocet dni dopredu. Pouzit pouze pro rozsireni hledani. |
| weekdays    | integer[]  | ne       |             | ISO dny v tydnu: pondeli=1 az nedele=7. |
| time_from   | string     | ne       |             | Nejdrivejsi prijatelny cas HH:MM. |
| time_to     | string     | ne       |             | Nejpozdejsi prijatelny cas HH:MM. |
| limit       | integer    | ano      | 3           | Pocet vracenych variant. |
| compact     | boolean    | ano      | true        | Kratka odpoved vhodna pro hlasoveho agenta. |

Kratky popis toolu:

Vyhledejte realne dostupne terminy v Medicus databazi. Tool volejte vzdy,
kdyz pacient hleda termin nebo zmeni lekare, sluzbu, datum, den v tydnu nebo
cas. Dostupnost neodhadujte z pameti ani ze starsiho vysledku. Pokud pacient
uvede konkretniho lekare, poslete jeho jmeno jako doctor_name.

Text k predani agentovi, ktery nastavuje ElevenLabs prompt:

Pridej tool doctor_availability. Agent ho ma zavolat vzdy, kdyz pacient hleda
volny termin nebo zmeni pozadovaneho lekare, sluzbu, datum nebo cas. Tool vraci
realne volne terminy z Medicus databaze v poli options. Pokud pacient uvede
lekare, agent preda jeho jmeno jako doctor_name a sam neurcuje doctor_id.
Pevne nastav limit=3 a compact=true.


TOOL 2: patient_lookup
======================

Endpoint:
POST {BASE_URL}/patient-lookup

Body parametry:

| name                      | type    | required | fixed value | description |
|---------------------------|---------|----------|-------------|-------------|
| phone                     | string  | ne       |             | Telefon volajiciho. Pri prvnim lookupu pouzit call metadata nebo dynamic variable, pokud je dostupna. |
| first_name                | string  | ne       |             | Krestni jmeno pacienta. |
| last_name                 | string  | ne       |             | Prijmeni pacienta. |
| birth_date                | string  | ne       |             | Datum narozeni ve formatu YYYY-MM-DD. |
| birth_number_last4        | string  | ne       |             | Posledni 4 cislice rodneho cisla pro overeni totoznosti. |
| birth_number              | string  | ne       |             | Cele rodne cislo. Pouzit hlavne pro test nebo pokud ho pacient vyslovne poskytne. |
| include_appointments      | boolean | ano      | true        | Po overeni vratit budouci objednavky. |
| include_past_appointments | boolean | ano      | false       | Po overeni vratit i historii. Pro bezny lookup vypnout. |

Kratky popis toolu:

Vyhledejte pacienta v Medicus kartotece. Primarne pouzijte telefon volajiciho.
Pokud telefon pacienta nenajde nebo vrati vice kandidatu, agent se doptava na
jmeno, prijmeni a pripadne datum narozeni a zavola tool znovu. Pokud odpoved
vrati status needs_verification, agent pozada o posledni 4 cislice rodneho
cisla a zavola tool znovu s birth_number_last4. Existujici objednavky lze
sdelovat pouze pokud verification.verified=true.

Text k predani agentovi, ktery nastavuje ElevenLabs prompt:

Pridej tool patient_lookup. Pokud je na zacatku hovoru dostupne telefonni cislo
volajiciho, agent ho pouzije pro prvni tichy lookup. Tool slouzi k overeni,
zda je pacient registrovany, k overeni totoznosti a po uspesnem overeni k
nacteni jeho budoucich objednavek.

Pokud tool vrati status=not_found, agent pozada o jmeno, prijmeni a datum
narozeni a lookup zopakuje. Pokud vrati status=multiple_matches, agent pozada
o doplnujici identifikacni udaje. Pokud vrati status=needs_verification, agent
pozada o posledni 4 cislice rodneho cisla a lookup zopakuje s parametrem
birth_number_last4. Existujici objednavky pacientovi nesdeluje, dokud neni
verification.verified=true.

Pevne nastav include_appointments=true a include_past_appointments=false.


Poznamky k testovaci verzi
==========================

- BASE_URL z trycloudflare se po restartu muze zmenit.
- Oba tooly jsou read-only.
- Agent se predstavuje za Dermatologicke stredisko Sumperk.
- Pokud je dostupny telefon volajiciho z webhooku/dynamic variable, agent ma
  na zacatku hovoru provest tichy patient_lookup.
- Volne terminy lze resit i pred overenim identity.
- Existujici objednavky se nesmi sdelovat pred verification.verified=true.
- Osobni udaje z lookupu agent nikdy nesdeluje volajicimu; pouziva je jen
  interne pro dohledani a overeni. Aktualni vyjimka jsou objednane terminy
  overeneho pacienta.
- Pri osobnich udajich a vybranem terminu ma agent udaj zopakovat a potvrdit.
- Telefonni lookup pouziva KARKONTAKT.
- patient_lookup sklada vice vstupnich parametru pomoci AND. Dalsi udaje tedy
  zpresnuji predchozi lookup.
- Registrace noveho pacienta zatim neni implementovana.
- Zapis terminu smi agent potvrdit pouze pokud appointment_write vrati ok=true.
